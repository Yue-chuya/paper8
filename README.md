# Research Paper Replication: AddressSanitizer
## Selected Paper
- **Paper**: AddressSanitizer: A Fast Address Sanity Checker
- **Paper Link**: https://www.usenix.org/system/files/conference/atc12/atc12-final39.pdf
- **Tool**: https://clang.llvm.org/docs/AddressSanitizer.html

## 1. Overview
This repository provides a **reduced-scale reproduction** of selected claims from *AddressSanitizer: A Fast Address Sanity Checker*. We use existing Clang/LLVM AddressSanitizer (ASan) instrumentation rather than reimplementing ASan from scratch.

**Purpose:**
The goal is to validate the paper's core claims regarding AddressSanitizer (ASan). Because SPEC CPU2006 is licensed software and was unavailable for us to use, we substitute a GEMM matrix-multiplication workload (`experiments/workload/gemm.c`) and targeted tests to evaluate ASan's functionality, performance overhead. On this basis, we have also further expanded the performance evaluation to a multi-threaded workload (`experiments/workload/gemm_thread.c`).

- **Claim 1 Memory-Error Detection**: 
Verifies ASan detection of memory bugs (use-after-free, double-free, heap, stack and global buffer overflow) compiled at `-O0 -fsanitize=address -g`.

- **Claim 2 Runtime and Memory Overhead**:
Measures execution time and peak memory usage across three runs (`-O2` baseline vs. `-O2 -fsanitize=address` ASan), comparing against the paper's reported ~73% slowdown and ~3.37x memory overhead.

- **Extension Experiment: Multi-Threaded GEMM Scalability and Overhead**:
Evaluates how scaling a constant total GEMM workload (`N=1000`) across `1`, `2`, `4`, and `8` POSIX threads affects runtime, parallel speedup, slowdown ratio, and memory_ratio (`-O2 -pthread` vs. `-O2 -pthread -fsanitize=address`, alongside `serial` and `serial_asan`). 
Details in `extension/extension_design.md`.

- **Limitations**:
Tests scenarios where ASan may miss bugs (far out-of-bounds beyond redzone, unaligned accesses, and quarantine exhaustion on use-after-free).

## 3. Setup
To reproduce the experiments on a clean machine without hard-coded paths, ensure the following environment and tools are available:

- **Supported Platforms**
    1. Linux (Ubuntu 22.04 on WSL2)
    - Kernel: `6.18.54.1-microsoft-standard-WSL2`
    - Compiler: clang `21.1.8 (6ubuntu1)`
    - Build and Shell: GNU Make `4.4.1`, GNU Bash `5.3.9(1)-release`
    - Hardware: `16 GB` RAM (13th Gen Intel(R) / AMD Ryzen 5 4500U)
    
    2. macOS (Apple Silicon) 
    - Kernel: `21.6.0 (Darwin)`
    - Compiler: clang `14.0.0`
    - Build and Shell: GNU Make `3.81`, GNU Bash `3.2.57(1)-release`
    - Hardware: `8 GB` RAM (Apple M2)

- **Python environment (for plotting)**
    - Python 3 with numpy and matplotlib: `pip install numpy matplotlib`

- **Key Settings Affecting Results**
    - Performance benchmark builds: `-O2` (baseline) and `-O2 -fsanitize=address` (ASan).

    - Extension builds: `-O2 -pthread` (Baseline) and `-O2 -pthread -fsanitize=address -fno-omit-frame-pointer` (ASan), across `1`, `2`, `4`, and `8` threads.
    
    - Bug detection and false-negative tests: `-O0 -fsanitize=address -g` to prevent compiler dead-code or undefined-behavior optimizations from removing injected faults prior to instrumentation.
    
    - Paper-parameter runs: `ASAN_OPTIONS="quarantine_size_mb=0:redzone=32:malloc_context_size=0"`

## 4. Build and Run Commands
All commands below assume you are in the repository root directory and use relative paths only.

1. Compile all targets: `make`
2. Run all experiments and generate figures: `make run`
3. Clean up all compiled binaries and temporary logs: `make clean`

## 5. Expected Outputs
- **Raw Logs** `(logs/)`
    - `logs/bug_tests/*.log`: ASan diagnostic outputs for the 5 memory-error test cases.
    - `logs/false_negative/*.log`: Execution outputs for the 3 false-negative cases.

- **Statistical Results** `(results/)`
    - `results/benchmark_result.md`: Raw per-run timings/peak memory and summary statistics (3 runs) under default ASan settings.
    - `results/paper_params_result.md`: Raw per-run timings/peak memory and summary statistics (3 runs) under paper parameters.
    - `results/extension_result.md`: Per-thread raw data, statistics, checksum verification (1 vs. 8 threads), and summary table for serial, serial_asan, pthread, and pthread_asan.

- **Visualizations** `(figure/)`
    - `figure/runtime_overhead.png` and `figure/memory_overhead.png`: Bar charts comparing Default Benchmark and Paper Params against the paper's reference values.
    - `figure/extension/*.png`: mean_time_plot.png, speedup_plot.png, slowdown_plot.png, memory_ratio_plot.png, and peak_memory_plot.png.

- **Verifications**
    - **Bug tests (`run_bug_tests.sh`)**: Each of the 5 test programs shows **"Bug WAS detected"**.
    - **False negatives (`run_false_negative.sh`)**: Each of the 3 boundary cases shows **"False Negative achieved"**. Behavior may vary across platforms/environments, so some cases may show **"Caught by ASan"**.

- **Results**   
    - **Main Benchmark (Default vs. Paper Params vs. Paper):**
        - **Default**
            - Slowdown: 74.50% (1.75x)
            - Memory Ratio: 2.51x

        - **Paper Parameters**
            - Slowdown: 68.81% (1.69x)
            - Memory Ratio: 2.51x

        - **Paper Reference (SPEC CPU2006)**
            - Slowdown: 73%
            - Memory Ratio: 3.37x
  
    - **Extension**
        - Slowdown:
            - 1T: 83.31% (1.83x)
            - 2T: 113.01% (2.13x)
            - 4T: 93.63% (1.94x)
            - 8T: 102.70% (2.03x)
        
        - Memory Ratio:
            - 1T: 2.52x
            - 2T: 2.53x
            - 4T: 2.53x
            - 8T: 2.52x
