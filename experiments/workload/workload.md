# Workload and Results

## 1. Benchmark Selection
- **Benchmark**: Self-contained `gemm.c` (Matrix Multiplication, Matrix Size N=1000).
- **Justification**: The original paper utilizes the SPEC CPU2006 suite, which was unavailable due to licensing and access constraints. As a valid reduced-scale substitute, we use a self-contained GEMM kernel that is compute-intensive and exercises the heap allocator. 
- **Traceability**: The raw logs and statistics are automatically recorded in `logs/benchmark_result.md`.

## 2. Experimental Setup
- **Automated Script**: `./scripts/run_benchmark.sh`
- **Baseline Compilation**: `clang -O2 experiments/workload/gemm.c -o demo_baseline`
- **ASan Compilation**: `clang -O2 -fsanitize=address experiments/workload/gemm.c -o demo_asan`
- **Environment**: Apple Silicon (macOS), Apple clang version 14.0.0.

## 3. Runtime and Memory Results (3 Runs)
*The following data is automatically generated by our statistical script to ensure accuracy.*

### Baseline (ASan OFF)
- **Runs**: 1.584134 s, 1.578419 s, 1.486961 s
- **Mean Runtime**: 1.5498 s
- **Standard Deviation (Std)**: 0.0445 s
- **Peak Memory**: 24.38 MB

### ASan (ASan ON)
- **Runs**: 2.597861 s, 2.602678 s, 2.590914 s
- **Mean Runtime**: 2.5972 s
- **Standard Deviation (Std)**: 0.0048 s
- **Peak Memory**: 61.44 MB

## 4. Performance Analysis (Paper vs. Ours)

| Metric | Original Paper | Our Reproduction | Analysis |
| :--- | :--- | :--- | :--- |
| **Runtime Slowdown** | ~73% (1.73x) | **67.58% (1.68x)** | Highly consistent trend. The slight difference (~5 percentage points) is due to using a single GEMM kernel instead of SPEC CPU2006, and modern compiler optimizations. |
| **Memory Overhead** | ~3.37x | **2.52x** | Same magnitude (ASan significantly inflates memory). The ratio is smaller for us because our N=1000 baseline footprint (24MB) is smaller than the large-scale SPEC benchmarks. |

### Final Verdict
Our independent measurement confirms the paper's core Claim 2.1: **AddressSanitizer imposes a significant runtime slowdown (approx. 68%) and a notable memory overhead (approx. 2.5x) during execution.** The results are consistent with the paper's reported averages, validating the tool's performance characteristics.
